# モノシリ JSTQB準拠テスト管理スキル

## 概要

JSTQB Foundation Level シラバス v4.0 に基づき、「モノシリ」のテスト活動を体系的に計画・設計・実行・管理する。プロジェクトナレッジにあるJSTQB要約ドキュメントを参照リソースとして活用する。

## モノシリの機能マップ（テスト対象の理解）

テスト設計の前提として、モノシリの主要機能を把握しておく。

### Phase 1（MVP）の機能
1. **起動・初期化**: ZIP解凍→exe起動→モデルDL（初回）→フォルダ選択
2. **インデックス作成**: ファイル読み込み→テキスト抽出→チャンク分割→Embedding→ベクトルDB格納
3. **差分インデックス**: SHA-256ハッシュによる変更検知、差分のみ再処理
4. **チャットUI**: 質問入力→ベクトルDB検索→ローカルLLM回答生成→エビデンス表示
5. **エビデンス表示**: ファイル名、パス、ページ/スライド番号、クリックで直接開く
6. **スキップログ**: 処理不能ファイルの一覧
7. **履歴タブ**: 過去の質問・回答の一覧表示＋キーワード検索
8. **類似度スライダー**: 0〜1の範囲でユーザー調整可能

### 対象ファイル形式
PDF, Word(.docx/.doc), PowerPoint(.pptx), Excel(.xlsx/.xls), テキスト系(.txt/.csv/.md), CAD(ファイル名のみ), 画像(ファイル名のみ)

### テスト用データ
ワークスペースのfinancial_reportsフォルダに日本企業・米国企業の財務レポートPDFが多数格納されている。これらをRAG機能のテストデータとして活用する。

## テストプロセス（JSTQB準拠）

以下の順序でテスト活動を進める。各ステップで具体的な成果物を作成する。

### STEP 2: テスト分析（何をテストするか）

仕様書から**テスト条件**を導出する。モノシリ固有のテスト条件は以下のカテゴリに分類する：

#### A. RAGパイプライン テスト条件
- テキスト抽出の正確性（各ファイル形式別）
- チャンク分割の適切性（500〜800トークン、オーバーラップ100）
- Embedding生成の品質
- ベクトルDB検索の精度（類似度スライダーとの連動）
- 回答生成の正確性と関連性

#### B. ファイル処理 テスト条件
- 対応形式（PDF, Word, PowerPoint, Excel, テキスト系）の正常処理
- 未対応形式のスキップとログ記録
- 破損ファイル、パスワード付きファイルの処理
- 大量ファイル（数百〜数千件）の処理
- 日本語ファイル名・パスの処理

#### C. インデックス管理 テスト条件
- 初回インデックス作成の完了
- SHA-256差分検知の正確性（新規/変更/削除）
- 進捗バーと時間見積もりの精度
- キャンセル機能の動作
- キャッシュの保存と読み込み

#### D. UI/UX テスト条件
- チャット画面の基本操作
- エビデンスのクリックでファイルが開く
- 類似度スライダーの動作
- 履歴タブの表示と検索
- 「該当なし」時のフォールバック動作

#### E. 非機能 テスト条件
- 起動時間（exe起動からチャット画面まで）
- インデックス作成速度（ファイル数別）
- 回答生成速度（ローカルLLM）
- メモリ使用量（7B/3Bモデル別）
- ストレージ使用量

### STEP 3: テスト設計（どのようにテストするか）

テスト条件からテストケースを導出する。以下のJSTQB技法を適用する：

#### 同値分割法の適用例（モノシリ向け）

**ファイル形式処理の同値パーティション:**
| パーティション | 値の例 | 期待結果 |
|---|---|---|
| 有効: PDF | sample.pdf | テキスト抽出成功 |
| 有効: Word | report.docx | テキスト抽出成功 |
| 有効: PowerPoint | slides.pptx | スライド別テキスト抽出 |
| 有効: Excel | data.xlsx | セルテキスト抽出 |
| 有効: テキスト | readme.txt | 全文読み込み |
| 無効: CAD | model.dwg | ファイル名のみ記録 |
| 無効: 画像 | photo.jpg | ファイル名のみ記録 |
| 無効: 未対応 | archive.7z | スキップ＋ログ記録 |

**類似度スライダーの同値パーティション:**
| パーティション | 値の範囲 | 期待結果 |
|---|---|---|
| 有効: 低い閾値 | 0.0〜0.3 | 広い範囲の結果を返す |
| 有効: 中間（デフォルト） | 0.4〜0.6 | バランスの良い結果 |
| 有効: 高い閾値 | 0.7〜1.0 | 絞り込まれた結果 |

#### 境界値分析の適用例

**チャンク分割の境界値:**
- チャンクサイズ: 499トークン（境界外）, 500トークン（境界）, 501トークン（境界内）
- チャンクサイズ: 799トークン（境界内）, 800トークン（境界）, 801トークン（境界外）
- オーバーラップ: 99トークン, 100トークン, 101トークン

**エビデンス表示件数の境界値:**
- 0件（該当なし）, 1件, 9件, 10件（上限）, 11件以上

**類似度スライダーの境界値:**
- -0.01（無効）, 0.0, 0.01, 0.49, 0.5（デフォルト）, 0.51, 0.99, 1.0, 1.01（無効）

#### デシジョンテーブルの適用例

**モード選択とAPI設定のデシジョンテーブル:**
| 条件 | R1 | R2 | R3 | R4 |
|---|---|---|---|---|
| モード | ローカル | ローカル | クラウド | クラウド |
| APIキー設定済み | N | Y | N | Y |
| **アクション** | | | | |
| ローカルLLM使用 | ○ | ○ | × | × |
| クラウドLLM使用 | × | × | × | ○ |
| エラー表示 | × | × | ○ | × |
| 警告表示 | × | ○※ | × | × |

※ローカルモードでAPIキーが設定されている場合は不要だが異常ではない

#### 状態遷移テストの適用例

**インデックス作成の状態遷移:**
```
[未開始] --フォルダ選択--> [フォルダ選択済み]
[フォルダ選択済み] --インデックス開始--> [処理中]
[処理中] --完了--> [完了]
[処理中] --キャンセル--> [キャンセル済み]
[処理中] --エラー--> [エラー]
[完了] --ファイル変更検知--> [差分更新待ち]
[差分更新待ち] --差分インデックス--> [処理中]
[キャンセル済み] --再開--> [処理中]
```

## テストピラミッドのモノシリへの適用

```
         ┌──────────────────┐
         │  E2E/受け入れテスト │ ← チャットで質問→正しい回答＋エビデンス
         ├──────────────────┤
         │  統合テスト        │ ← RAGパイプライン全体、UI⇔バックエンド
         ├──────────────────┤
         │  コンポーネントテスト │ ← テキスト抽出、チャンク分割、Embedding、検索
         └──────────────────┘
```

- **コンポーネントテスト（多数・自動化）**: 各ファイル形式のテキスト抽出、チャンク分割ロジック、SHA-256差分検知、ベクトルDB CRUD操作
- **統合テスト（中程度）**: RAGパイプライン全体（抽出→チャンク→Embedding→検索→回答）、UI操作→バックエンド処理→結果表示
- **E2E/受け入れテスト（少数・手動含む）**: 実際の財務レポートPDFで質問→回答品質の評価、エビデンスクリック→ファイルが開く

## リスクベースドテスト（モノシリ固有リスク）

| リスクID | リスク内容 | 影響度 | 発生確率 | リスクレベル | テスト対応 |
|---|---|---|---|---|---|
| PR-001 | 日本語テキスト抽出の精度不足 | 高 | 中 | 高 | 多種の日本語PDFで網羅テスト |
| PR-002 | 大量ファイルでのメモリ不足 | 高 | 中 | 高 | 負荷テスト（100/500/1000件） |
| PR-003 | ローカルLLMの回答品質不足 | 中 | 高 | 高 | 回答品質評価テスト |
| PR-004 | チャンク分割による文脈の喪失 | 中 | 中 | 中 | 文脈依存質問テスト |
| PR-005 | 差分検知の誤判定 | 中 | 低 | 中 | ファイル操作シナリオテスト |
| PR-006 | エビデンスのページ番号ずれ | 低 | 中 | 中 | 複数形式で正確性検証 |
| PR-007 | PCスペック不足での動作不良 | 高 | 中 | 高 | 最低スペック環境テスト |

## 探索的テスト チャーター（モノシリ向け）

形式的テスト技法では拾いきれない問題を探索的テストで補完する。

**チャーター例:**
1. 「製造業の専門用語（金型、切削条件、公差等）を含むPDFでRAG精度を探索する」（60分セッション）
2. 「日本語と英語が混在した資料でインデックス作成と検索の挙動を探索する」（45分セッション）
3. 「ネットワーク切断状態でのアプリ全機能の動作を探索する」（30分セッション）
4. 「パスワード付きPDF、破損Excel、空のPowerPointなど異常ファイルの処理を探索する」（45分セッション）
