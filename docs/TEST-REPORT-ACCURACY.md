## チャンク品質の分析

> ユーザー指摘: 「テスト中に気になったんだけど、チャンク生成は問題がないの？」

コードレビュー（`core/extractor.py` / `core/indexer.py`）を実施した。回答精度に影響する構造的な問題を4件特定した。

### CHUNK-001: テーブルの行境界での分割（優先度 高）

**問題:** `RecursiveCharacterTextSplitter(chunk_size=1200, chunk_overlap=300)` はテキスト長でのみ分割する。PDFの財務テーブル（例: 売上高・受注高一覧）は「ヘッダー行 + データ行」の構造だが、行の途中でchunkが切れると、後のchunkにヘッダーコンテキストが含まれなくなる。

```
【分割前】
  売上高（百万円）: 2019: 7,623,374 / 2020: 7,459,028 / 2021: 8,729,196

【分割後 (最悪ケース)】
  chunk A: "...売上高（百万円）: 2019: 7,623,374 / 2020: 7,4"
  chunk B: "59,028 / 2021: 8,729,196..."
```

chunk Bには「これが売上高の数値である」という文脈がない。RAGがchunk Bを取得しても、LLMは何の数値か判断できない。

**影響:** BUG-034（存在情報の誤「記載なし」）の根本原因の一つ。特にExcel/PDF財務データ。

**改善案:**
- `chunk_size` をテーブル行の平均長に応じて調整（現状1200は大きすぎる可能性）
- テーブル検出後はテーブル単位で1チャンクとする「Table-aware splitting」の実装
- `chunk_overlap=300` をテーブル構造が必ずかぶる値に増加（例: 500〜600）

---

### CHUNK-002: ドキュメント階層の消失（優先度 高）

**問題:** `_extract_docx()` はすべての段落とテーブルセルをフラットに結合する。セクションヘッダー（例: 「3. 財務情報」「4. 役員情報」）が次のchunkに引き継がれない。

```python
# extractor.py — 現状の実装
for para in doc.paragraphs:
    parts.append(para.text)
for table in doc.tables:
    for row in table.rows:
        for cell in row.cells:
            parts.append(cell.text)
```

結果として生成されるchunkは「どのセクションの情報か」という文脈を持たない。

**影響:** 類似した数値が複数セクションに存在する場合（例: 単体売上高 vs 連結売上高）、LLMがどちらを指すか判断できない。

**改善案:**
```python
# セクションヘッダーをchunk先頭に付与する実装例
current_section = ""
for para in doc.paragraphs:
    if para.style.name.startswith("Heading"):
        current_section = para.text
    else:
        parts.append(f"[{current_section}] {para.text}" if current_section else para.text)
```

---

### CHUNK-003: Excel行列関係の消失（優先度 中）

**問題:** `_extract_xlsx()` は全セル値を単純に結合する。Excelのクロス集計表（行=年度、列=指標）は構造が失われ、意味不明な数値の羅列になる。

```
【Excelの実際の構造】
        | 売上高 | 営業利益 | 純利益
  2019  | 7,623  | 523      | 284
  2020  | 7,459  | 498      | -196

【抽出後の文字列】
  "2019 7623 523 284 2020 7459 498 -196 ..."
```

**影響:** Excel財務データへの質問精度が低い。特に「〇〇年の〇〇」という特定クエリ。

**改善案:** `openpyxl` でrow/col構造を保持したMarkdown表形式に変換してからチャンク化する。

---

### CHUNK-004: ページ境界テーブルの分断（優先度 中）

**問題:** PyMuPDFはページ単位でブロック抽出する。1つのテーブルが複数ページにまたがる場合、ページ境界でテーブルが分割され、後半ページのchunkにはヘッダー行が含まれない。

**影響:** 複数ページにわたる財務一覧表（例: 5年間の業績サマリー）の後半データが「何の数値か」不明になる。

**改善案:** ページ末尾のブロック座標と次ページの先頭ブロック座標を比較し、テーブル継続の検出を試みる（実装難易度: 高）。短期対応としては `chunk_overlap` を増加させて後半chunkにヘッダーが含まれる確率を上げる。
