## テスト中に発見・修正したバグ

### BUG-010: StreamlitDuplicateElementKey エラー（複数ターン）
- **症状:** 同じファイルが複数ターンの参照元に現れると key が衝突し `StreamlitDuplicateElementKey` エラー
- **原因:** `render_evidence()` を呼ぶ際に一意でない `key_prefix` を渡していた
- **修正:** `chat_page.py` の履歴ループで `key_prefix=f"ev_{i_msg}"` を渡すよう変更
- **ファイル:** `ui/chat_page.py`

### BUG-011: `==文書終わり==` がストリーミング回答に漏れる
- **症状:** プロンプトの区切り文字 `==文書終わり==` がモデルによってエコーされ、回答に表示
- **原因:** (1) Ollama stop tokens に `"==文書終わり=="` が未設定、(2) ユーザーメッセージに閉じセパレータがあり、モデルがそれをエコーした
- **修正:** 
  - `_build_messages_with_history()` から `==文書終わり==` を削除（閉じタグなし形式に変更）
  - stop tokens に `"==文書終わり"`, `"==社内文書=="` を追加
- **ファイル:** `core/llm.py`

### BUG-012: 正解回答後に meta-commentary が追加される
- **症状:** 「小早川智明です。」という正解の後に「社内資料に該当情報はありませんでした。```」「質問に直接関連する情報が含まれていなかったため...」などが追加される
- **原因:** ユーザーメッセージに「社内資料に該当情報はありませんでした」というフレーズを含めていたため、モデルが正解後にこのフレーズをmeta-commentaryとして生成した
- **修正:**
  - ユーザーメッセージからこのフレーズを削除（system promptのみで管理）
  - ユーザーメッセージを「答えたら終了。」のみのシンプル形式に変更
  - stop tokens に `"```"`, `"\n\n社内資料"`, `"\n\n質問に直接"` を追加
  - 後処理にも同様のパターンを追加
- **ファイル:** `core/llm.py`

## 総評

ADR-002で特定した根本原因（フォールバック設計・パラメータ設定・量子化モデルの指示追従限界）の修正により、以下が達成された：

- **ハルシネーション大幅削減**: フォールバック廃止により「関係ない文書からの嘘の回答」がなくなった
- **速度30〜50%改善**: Qwen2.5-7BのMAX_TOKENS 4096→1024、TOP_K 30→15による推論速度改善
- **回答品質向上**: stop tokens・後処理・プロンプト改善の多層防御でクリーンな回答が安定して得られるようになった
- **UIバグ修正**: 複数ターンの参照元ボタン表示が正常動作
