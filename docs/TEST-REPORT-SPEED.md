## 背景・課題

ADR-002（BUG-007〜012修正）後も、応答が遅すぎる問題が継続していた。

## 実施した最適化（SPEED-001〜004）

### SPEED-001: BUG-031対応 — keep_alive=30m + warmup改善
- **変更:** `generate_answer()` / `stream_answer()` / `warmup_model()` の全Ollamaリクエストに `"keep_alive": "30m"` を追加
- **変更:** `app.py` の `_warmup_model_if_needed()` を `/api/ps` で実際のロード状態を確認してから起動するよう改修
- **変更:** warmup timeout 60s → 120s
- **ファイル:** `core/llm.py`, `app.py`
- **効果:** コールドスタート後の30分間はモデルがVRAMに保持される

### SPEED-002: per-request warmupの削除
- **変更:** `generate_answer()` / `stream_answer()` 内から `warmup_model()` 呼び出しを削除
- **背景:** BUG-031修正として各リクエスト前にwarmupを追加していたが、2〜5秒のオーバーヘッドが発生していた
- **ファイル:** `core/llm.py`
- **効果:** 毎リクエストの2〜5秒オーバーヘッド排除

### SPEED-003: n_ctx削減（4096→2048）
- **変更:** `register_model_with_ollama()` 内の `n_ctx = 4096` → `n_ctx = 2048`
- **理由:** KVキャッシュが VRAM 8GB の最大の消費源。2048でRAGコンテキスト（~1500トークン）は十分収まる
  - n_ctx=4096: ~1.6GB VRAM消費
  - n_ctx=2048: ~0.8GB VRAM消費（約0.8GB節約）
- **ファイル:** `core/llm.py`
- **後処理:** UIの「🔄 再登録」ボタンでOllama Modelfileに反映済み（context_length=2048 確認）

### SPEED-004: MAX_TOKENS削減（1024→512/384）
- **変更:** `LLM_MODEL_MAX_TOKENS` の全モデル設定を削減
  - 14B: 1024 → 512
  - 7B: 1024 → 512（推奨モデル）
  - 3B: 1024 → 384
  - Qwen3.5-9B: 1024 → 512
  - Nemotron-9B: 1024 → 512
- **理由:** 社内RAGの典型回答は100〜300トークン。512で十分。過剰生成による速度低下を防ぐ
- **ファイル:** `core/config.py`

### SPEED-005: 推奨モデル変更（Qwen3.5-9B → Qwen2.5-7B）
- **変更:** UIから使用モデルを Qwen3.5-9B(5.7GB) → Qwen2.5-7B(4.8GB) に切り替え
- **理由:** VRAM 8GBでは7Bの方がVRAM使用率が低く、KVキャッシュ用余裕が生まれる

## 分析: 目標5秒に未達の要因

| フェーズ | 推定時間 | 説明 |
|---------|---------|------|
| ベクトル検索 | 2〜3秒 | 7,087チャンクからTOP_K=15件取得 |
| LLMプリフィル | 2〜3秒 | RAGコンテキスト約1,500トークンを処理 |
| LLM生成 | 3〜5秒 | 100〜150トークン / RTX 4060 Ti ≈ 45tok/s |
| **合計（ウォーム）** | **約8〜12秒** | |

RTX 4060 Ti はQwen2.5-7B Q4_K_Mで約45tok/sが期待値。  
5秒目標達成には「LLMプリフィル短縮 + 生成量削減」が必要。

## 残存課題と推奨追加最適化

### 優先度 高

#### SPEED-006（未実施）: RAG_CONTEXT_MAX_LENGTH削減
- **変更案:** `RAG_CONTEXT_MAX_LENGTH`: 3000 → 1500文字
- **期待効果:** プリフィルトークン数が約半減 → プリフィル時間 -1〜2秒
- **リスク:** 長文回答が必要な質問で情報が欠落する可能性

#### SPEED-007（未実施）: TOP_K削減
- **変更案:** `TOP_K`: 15 → 8
- **期待効果:** 検索時間短縮 + コンテキストサイズ縮小 → 計 -0.5〜1秒
- **リスク:** 関連チャンクを見逃すリスクが若干増加

#### SPEED-008（代替案）: Qwen2.5-3Bへ変更
- **変更案:** 使用モデルをQwen2.5-3B（2GB）に変更
- **期待効果:** 推論速度 ~90〜120tok/s → 150トークン ≈ 1.5秒 → **総計4秒以内**で目標達成
- **リスク:** 7Bに比べ回答精度が低下（特に専門用語・複雑な質問）

### 優先度 中

#### 回答品質 vs 速度バランス調整
- MAX_TOKENSをさらに 512 → 256 に削減することで追加 +1秒速度改善も可能（回答が短くなる）
